# 塔防战斗系统接入使用说明

本文档基于当前项目真实代码整理，目标是让第一次接触该模块的人可以完成场景搭建、战斗初始化、Prefab 制作、配置填写，并把塔防战斗跑起来。

相关代码入口：

- `GameplayModeBase.cs`
- `GameplaySwitchRequest.cs`
- `PveGameplayMode.cs`
- `BattleFoundation/Core/BattleEngine.cs`
- `BattleFoundation/Core/BattleContext.cs`
- `TowerDefense/Core/TDBattleEngine.cs`
- `TowerDefense/Config/TowerDefenseGlobalConfig.cs`

注意：`TDBattleEngine` 的创建和 Tick 驱动已经接入 `PveGameplayMode`。进入 PVE 时传入 `TowerDefenseGlobalConfig`，且 `StartImmediately=true`，`PveGameplayMode.EnterAsync` 会创建 `TDBattleEngine`、调用 `Initialize/StartBattle`，并订阅 `GameplayTickEvent` 来驱动 `UpdateFromUnity`。退出 PVE 时会释放 Tick 订阅和战斗引擎。

## 1. 整体使用流程

### 1.1 创建场景

当前 `PveGameplayMode` 固定加载场景名：

```csharp
private const string SceneName = "PVE";
```

因此最直接的接入方式是创建或使用名为 `PVE` 的 Unity 场景。

### 1.2 进入 PVE GameplayMode

上层 Gameplay 流程入口在 `GameplayRuntime`：

```csharp
await GameplayRuntime.Instance.EnterPveAsync(
    chapterId: 1,
    sectionId: 101,
    startImmediately: true,
    tdConfig: towerDefenseGlobalConfig);
```

调用链：

```text
GameplayRuntime.EnterPveAsync
-> GameplayFlowMachine.SwitchToAsync
-> PveGameplayMode.LoadAsync
-> Context.Systems.Scenes.LoadSceneAsync("PVE", LoadSceneMode.Single, ...)
-> PveGameplayMode.EnterAsync
-> Context.Systems.Ui.Open<BattleMainView>()
-> PveGameplayMode.StartTowerDefenseBattle
-> new TDBattleEngine(tdConfig)
-> Initialize / StartBattle
-> GameplayTickEvent 驱动 UpdateFromUnity
```

`GameplaySwitchRequest` 负责携带切换参数，例如：

```csharp
GameplaySwitchRequest
    .To(GameplayModeId.Pve, GameplaySwitchReason.UserAction)
    .Set("ChapterId", chapterId)
    .Set("SectionId", sectionId)
    .Set("StartImmediately", startImmediately)
    .Set("TDConfig", towerDefenseGlobalConfig)
    .SetDebugName($"Enter PVE {chapterId}-{sectionId}");
```

### 1.3 启动塔防战斗入口

塔防战斗入口在 `PveGameplayMode` 内。推荐通过 `GameplayRuntime.EnterPveAsync` 传入 `TowerDefenseGlobalConfig`：

```csharp
await GameplayRuntime.Instance.EnterPveAsync(
    chapterId: 1,
    sectionId: 101,
    startImmediately: true,
    tdConfig: towerDefenseGlobalConfig);
```

`PveGameplayMode` 内部负责：

```text
StartTowerDefenseBattle
-> new TDBattleEngine(_tdConfig)
-> Initialize
-> StartBattle
-> 创建 TDBattleUIBridge
-> 写入 Blackboard: Pve.TDBattleEngine / Pve.TDBattleBridge
-> 订阅 GameplayTickEvent
```

### 1.4 战斗框架初始化顺序

`TDBattleEngine.Initialize()` 内部流程来自 `BattleEngine`：

```text
TDBattleEngine.Initialize
-> BattleEngine.InitializeRuntime
-> CreateRuntimeSettings
-> CreateContext
-> Context.Initialize
-> TDBattleEngine.OnInitialize
-> Phase = Ready
```

`TDBattleEngine.OnInitialize()` 注册系统顺序：

```text
PathFollowerSystem
-> MainCitySystem
-> CityAttackerSystem
-> CombatProjectileSystem
-> TowerPlacementSystem
-> TDPlayerMovementSystem
-> TDPlayerSkillInputSystem
-> TDEventSystem
-> EconomySystem
-> BuildSynergySystem
-> RoguelikeChoiceSystem
-> WaveManagerSystem
-> TDBattlePhaseSystem
-> VictoryCheckSystem
```

同时会注册 BattleRule：

```text
MainCityDestroyedRule
AllWavesClearedRule
```

### 1.5 NPC / 怪物 / 塔如何生成

怪物生成：

```text
WaveManagerSystem.Update
-> SpawnEnemyFromPath
-> TDBattleEngine.EnqueueCommand(WaveSpawnerCommand)
-> BattleEngine.ExecutePendingCommands
-> WaveSpawnerCommand.OnExecute
-> EnemyFactory.Allocate
-> TDEnemyActor.InitEnemy
-> EntityManager.AddEntity
```

防御塔生成：

```text
TowerPlacementSystem.TryBuildTower
-> TDBattleContext.SpendGold
-> TowerBuilderComponent.CanPlace
-> new TowerActor
-> TowerActor.InitTower
-> EntityManager.AddEntity
-> EventBus.Emit(TowerBuilt)
```

玩家 / NPC：

当前 `TDBattleEngine` 不会自动生成玩家。项目已有 `TDPlayerActor`，但需要外部手动创建并注入系统。

```csharp
var player = new TDPlayerActor();
player.InitPlayer(100, 10, 0, 5, spawnPos, playerPrefab);
engine.Context.EntityManager.AddEntity(player);

engine.Context.GetSystem<TDPlayerMovementSystem>().Player = player;
engine.Context.GetSystem<TDPlayerSkillInputSystem>().Player = player;
```

### 1.6 进入战斗循环

每帧必须调用：

```csharp
_engine.UpdateFromUnity(Time.deltaTime);
```

`BattleEngine.UpdateFromUnity()` 内部会：

```text
unityDeltaTime * TimeScale
-> ExecutePendingCommands
-> Context.Update
-> TDBattleEngine.OnUpdate
-> Context.LateUpdate
-> TDBattleEngine.OnLateUpdate
-> CheckEndConditions
-> RecordFrame
```

### 1.7 结束战斗

失败链路：

```text
EnemyReachedEnd
-> MainCityHealthComponent.TakeDamage
-> MainCityDestroyedEvent
-> MainCityDestroyedRule
-> BattleEngine.EndBattle(EBattleResult.Lose)
```

胜利链路：

```text
WaveManagerSystem.AllWavesCleared
-> VictoryCheckSystem
-> EventBus.Emit(AllWavesCleared)
-> AllWavesClearedRule
-> BattleEngine.EndBattle(EBattleResult.Win)
```

结束后：

```text
TDBattleEngine.OnBattleEnd
-> LevelManager.Instance.OnBattleEnded
-> EnemyFactory.RecycleAll
-> TDBattleContext.ClearServices()
```

## 2. Unity 场景结构说明

推荐场景结构：

```text
PVE
├── MapRoot
│   ├── Ground
│   ├── BlockedArea
│   └── Visuals
├── Main Camera
├── Canvas / UIRoot
└── EventSystem
```

### 2.1 必须 GameObject

`Ground`

- 用于防御塔放置射线检测。
- 必须有 Collider。
- Layer 需要能被 `TowerDefenseGlobalConfig.PlacementLayerMask` 命中。

`Canvas / UIRoot`

- 如果使用当前 UI 桥接，需要走 `UIRuntime` 打开 `TDHudViewBridged`、`TDRoguelikeChoiceView` 等 View。
- UI View 的绑定节点名需要与 `[UI]` 字段名匹配。

`EventSystem`

- 使用 UGUI Button 时必须存在。

### 2.2 可选 GameObject

`BlockedArea`

- 用于不可建造区域检测。
- Layer 需要被 `TowerDefenseGlobalConfig.BlockedLayerMask` 命中。

`MapRoot / Visuals`

- 纯表现节点，战斗逻辑不依赖。

### 2.3 是否需要 BattleRoot / Manager 节点

不需要额外的 `BattleRoot / Manager` 节点来创建战斗引擎。当前接入方式由 `PveGameplayMode` 负责：

- 从 `GameplaySwitchRequest` 读取 `TDConfig` / `TowerDefenseConfig`
- 创建 `TDBattleEngine`
- 调用 `Initialize`
- 调用 `StartBattle`
- 订阅 `GameplayTickEvent` 并驱动 `UpdateFromUnity`
- 退出 PVE 时 `Dispose`

### 2.4 Camera / UI / EventSystem 配置

- Camera 不被战斗系统直接读取。
- 建塔点击转世界坐标时，需要你自己的输入脚本使用 Camera 射线。
- `TDTowerBuildView` 当前只发出塔类型事件，不包含世界坐标，不能独立完成实际建塔。

### 2.5 场景启动顺序

```text
GameFacade.StartUp
-> new GameplayRuntime
-> GameplayRuntime.EnterPveAsync
-> PveGameplayMode.LoadAsync 加载 PVE
-> PveGameplayMode.EnterAsync 打开 BattleMainView
-> TDBattleEngine.Initialize
-> TDBattleEngine.StartBattle
-> GameplayTickEvent 驱动战斗 Tick
```

## 3. Prefab 规范

当前实现中，怪物、塔、主城 Prefab 主要是视觉表现。真正的战斗主体不是挂在 Prefab 上的 MonoBehaviour，而是运行时代码创建的 `BattleEntity` / `CombatActor`。

也就是说：

- 不需要在怪物 Prefab 上挂 `TDEnemyActor`。
- 不需要在塔 Prefab 上挂 `TowerActor`。
- 不需要在主城 Prefab 上挂 `MainCityActor`。
- 属性、技能、路径、攻击组件由代码添加到运行时 Entity 上。

### 3.1 怪物 Prefab

推荐结构：

```text
EnemyPrefab
├── Model
├── Animator                 // 可选，TDEnemyActor 会 GetComponentInChildren<Animator>()
├── AnimancerComponent       // 可选，CombatActor 延迟查找
├── PlayableDirector         // 可选，CombatActor 延迟查找
└── Collider                 // 可选，当前路径移动和索敌不依赖碰撞体
```

战斗主体：

- 运行时类型：`TDEnemyActor`
- 生成位置：`WaypointPath.Waypoints[0]`
- 移动方式：`PathFollowerComponent`
- 驱动系统：`PathFollowerSystem`

运行时自动处理：

```text
TDEnemyActor.InitEnemy
-> Add/Get PathFollowerComponent
-> PathFollowerComponent.Init(path, speed)
-> Get CombatAttributeComponent
-> 设置 HP / MaxHP / Attack / Defense / MoveSpeed
-> Instantiate Prefab
-> GetComponentInChildren<Animator>
```

必须填写的配置在 `TDEnemyConfig`：

- `Prefab`
- `MoveSpeed`
- `MaxHp`
- `Atk`
- `Def`
- `HitRadius`
- `KillGold`
- `LeakDamage`
- `CanAttackCity`
- `CityAttackInterval`
- `IsBoss`
- `BossHpMultiplier`
- `BossSpeedMultiplier`
- `BossKillGold`

事件：

- 生成：`TDEventIds.EnemySpawned`
- Boss 生成：`TDEventIds.BossSpawned`
- 击杀：`TDEventIds.EnemyKilled`
- 到达终点：`TDEventIds.EnemyReachedEnd`

### 3.2 防御塔 Prefab

推荐结构：

```text
TowerPrefab
├── Model / TurretRoot       // 实例化后作为 TowerActor.ViewTransform
├── Animator                 // 可选
└── FirePoint                // 当前代码未自动查找；如需精确发射点，需要扩展 FirePosition
```

战斗主体：

- 运行时类型：`TowerActor`
- 创建接口：`TowerPlacementSystem.TryBuildTower`
- 攻击驱动：`TowerPlacementSystem.Update`

运行时自动添加：

```text
CombatAttributeComponent
CombatAbilityComponent
TDTargetingComponent
TowerAttackComponent
TowerUpgradeComponent
```

必须填写的配置在 `TowerConfig`：

- `TowerName`
- `TowerType`
- `TowerLevel`
- `Prefab`
- `BuildCost`
- `UpgradeCost`
- `AttackRange`
- `AttackInterval`
- `AttackDamage`
- `AttackAbility`
- `ProjectileDefinition`
- `TargetPriority`
- `SlowEffect`
- `UpgradeConfig`

攻击链路：

```text
TowerPlacementSystem.Update
-> tower.Targeting.Update
-> tower.Attack.Update
-> TowerAttackComponent.PerformAttack
-> CombatAbilityComponent.TryActivateAttackAbility
-> RemoteAttackAbilityDefinition
-> AbilityTaskSpawnProjectile
-> ProjectileRuntime
-> CombatDamageExecution
```

重要：`TowerAttackComponent` 实际调用的是 `CombatAbilityComponent.TryActivateAttackAbility(target)`。如果 `TowerConfig.AttackAbility` 没配，塔可能能索敌，但攻击能力会激活失败。

事件：

- 建造：`TDEventIds.TowerBuilt`
- 升级：`TDEventIds.TowerUpgraded`
- 出售：`TDEventIds.TowerSold`
- 攻击：`TDEventIds.TowerAttack`
- 技能释放：`TDEventIds.TowerSkillCast`
- 切换目标：`TDEventIds.TowerTargetSwitch`

### 3.3 主城 Prefab

推荐结构：

```text
MainCityPrefab
└── Model / Visual
```

战斗主体：

- 运行时类型：`MainCityActor`
- 生成系统：`MainCitySystem`
- 血量组件：`MainCityHealthComponent`

必须填写的配置在 `MainCityConfig`：

- `CityName`
- `MaxHp`
- `Defense`
- `Prefab`

当前生成位置：

```csharp
mainCitySystem?.SpawnMainCity(_tdConfig?.MainCityConfig, Vector3.zero);
```

注意：`MapConfig.MainCityPosition` 当前没有被 `TDBattleEngine.OnBattleStart()` 使用。

### 3.4 玩家 / NPC Prefab

当前塔防引擎不会自动生成玩家或 NPC。

如果需要玩家角色，可使用：

```text
PlayerPrefab
├── Model
├── Animator
├── AnimancerComponent       // 可选
└── PlayableDirector         // 可选
```

外部代码创建：

```csharp
var player = new TDPlayerActor();
player.InitPlayer(
    maxHp: 100,
    atk: 10,
    def: 0,
    moveSpeed: 5,
    spawnPosition: spawnPos,
    prefab: playerPrefab);

engine.Context.EntityManager.AddEntity(player);
engine.Context.GetSystem<TDPlayerMovementSystem>().Player = player;
engine.Context.GetSystem<TDPlayerSkillInputSystem>().Player = player;
```

## 4. 战斗框架接入方式

### 4.1 在哪里调用战斗入口

当前推荐位置：

- `PveGameplayMode.EnterAsync`

当前 `PveGameplayMode.EnterAsync` 会先做基础 PVE 进入逻辑：

```csharp
Context.Systems.Audio.PlayBgm("bgm_pve");
Context.Systems.Ui.Open<BattleMainView>();
Context.Blackboard.Set("Pve.ChapterId", _chapterId);
Context.Blackboard.Set("Pve.SectionId", _sectionId);
```

随后当 `StartImmediately=true` 且请求中携带 `TDConfig` / `TowerDefenseConfig` 时，调用 `StartTowerDefenseBattle()` 创建并启动 `TDBattleEngine`。

### 4.2 初始化 BattleEngine

```csharp
var engine = new TDBattleEngine(tdGlobalConfig);
engine.Initialize();
engine.StartBattle();
```

`TowerDefenseGlobalConfig` 会在 `TDBattleEngine` 中提供：

- 随机种子
- 初始时间缩放
- 初始金币
- 预热敌人池
- 波次配置
- 主城配置
- 默认路径
- 建塔 LayerMask
- Roguelike / Synergy / Meta / Balance / Level 配置

### 4.3 注册怪物 / 塔 / 玩家

怪物不要手动注册，走波次系统。

塔用：

```csharp
var towerSystem = engine.Context.GetSystem<TowerPlacementSystem>();
towerSystem.TryBuildTower(towerConfig, worldPosition, out var tower);
```

玩家需要手动注册：

```csharp
engine.Context.EntityManager.AddEntity(player);
```

### 4.4 启动 Tick

```csharp
private void Update()
{
    engine?.UpdateFromUnity(Time.deltaTime);
}
```

不要让每个怪物或塔自己写 Unity `Update`。当前框架要求通过 `BattleEngine` 和 `IBattleSystem` 驱动。

### 4.5 时间缩放

初始值：

```text
TowerDefenseGlobalConfig.InitialTimeScale
-> TDBattleEngine.CreateRuntimeSettings
-> BattleEngine.TimeScale
```

运行时：

```csharp
engine.TimeScale = 0f;   // 暂停模拟
engine.TimeScale = 1f;   // 正常速度
engine.TimeScale = 2f;   // 双倍速度
```

`RoguelikeChoiceSystem` 会在选择阶段把 `TimeScale` 设为 `0f`，选择完成后恢复 `1f`。

### 4.6 结束战斗

主动结束：

```csharp
engine.EndBattle(EBattleResult.Win);
engine.EndBattle(EBattleResult.Lose);
```

自动结束：

- 主城 HP 为 0，触发失败。
- 全部波次清空且没有存活敌人，触发胜利。

销毁场景或退出模式时：

```csharp
engine.Dispose();
```

### 5.6 Buff / 技能配置如何生效

塔攻击：

```text
TowerConfig.AttackAbility
-> CombatAbilityComponent.GrantAbility
-> TowerAttackComponent.PerformAttack
-> TryActivateAttackAbility
```

投射物：

```text
TowerConfig.ProjectileDefinition
-> TowerActor.ProjectileDefinition
-> RemoteAttackAbilityDefinition / AbilityTaskSpawnProjectile 使用
```

Roguelike 强化：

```text
ChoiceConfig.AppliedEffect
-> RoguelikeChoiceSystem.ApplyChoiceEffect
-> CombatAbilityComponent.Effects.ApplySpecToSelf
```

如果 `AppliedEffect` 为空，`RoguelikeChoiceSystem` 会按 `ValueModifier` 直接改属性。

协同强化：

```text
SynergyConfig.BonusEffect
-> BuildSynergySystem
-> 达到 RequiredTowerType + RequiredCount 后应用
```

## 6. 运行时调试方法

### 6.1 快速测试战斗

1. 创建上述最小配置。
2. 调用 `GameplayRuntime.Instance.EnterPveAsync(..., startImmediately: true, tdConfig: towerDefenseGlobalConfig)`。
3. Play。
4. Console 应看到：

```text
[TDBattleEngine] Battle started
[WaveManager] Wave 1/... preparing
[MainCitySystem] Main city ... spawned
```

### 6.2 快速生成测试怪物

推荐通过波次生成，不要直接 Instantiate Prefab。

如果要临时测试，可在启动后调用：

```csharp
var path = tdConfig.DefaultPath;
var enemyConfig = tdConfig.WaveConfigs[0].EnemyEntries[0].Config;
engine.EnemyFactory.Allocate(enemyConfig, path, path.Waypoints[0]);
```

### 6.3 快速建测试塔

```csharp
var towerSystem = engine.Context.GetSystem<TowerPlacementSystem>();
var towerConfig = tdConfig.AvailableTowers[0];
towerSystem.TryBuildTower(towerConfig, new Vector3(2, 0, 0), out var tower);
```

如果失败，检查：

- 金币是否足够。
- `PlacementLayerMask` 是否能射线命中地面。
- `BlockedLayerMask` 是否挡住。
- 位置是否已经被 `_occupiedPositions` 占用。

### 6.4 查看统计

```csharp
var eventSystem = engine.Context.GetSystem<TDEventSystem>();
Debug.Log(eventSystem.TotalEnemySpawned);
Debug.Log(eventSystem.TotalEnemyKilled);
Debug.Log(eventSystem.TotalDamageToCity);
Debug.Log(eventSystem.GetAliveEnemyCount());
```

### 6.5 查看属性变化

```csharp
var attrs = enemy.Get<BattleCommon.CombatAttributeComponent>();
Debug.Log($"{attrs.HP}/{attrs.MaxHP}, Atk={attrs.Attack}, Def={attrs.Defense}");
```

### 6.6 常用事件监听

```csharp
engine.Context.EventBus.On<EnemyKilledEvent>(
    TDEventIds.EnemyKilled,
```

## 7. 常见错误与注意事项

### 7.1 Prefab 漏挂组件

当前战斗主体组件不是 MonoBehaviour，不需要挂到 Prefab。

但视觉组件缺失会影响表现：

- 没有 `Animator`：不会缓存动画组件。
- 没有模型：逻辑能跑，但看不见。
- 没有 Collider：当前怪物路径移动和塔索敌不依赖 Collider，但建塔地面必须有 Collider。

### 7.2 战斗无法启动

常见原因：

- 进入 `PveGameplayMode` 时没有传入 `TDConfig` / `TowerDefenseConfig`。
- `StartImmediately=false`，因此没有自动启动战斗。
- `PveGameplayMode.StartTowerDefenseBattle()` 没有执行。
- `GameplayRuntime.Tick` 没有被 `GameFacade.Update` 驱动，导致没有 `GameplayTickEvent`。
- `TowerDefenseGlobalConfig` 为空。

### 7.3 怪物不生成

检查：

- `TowerDefenseGlobalConfig.WaveConfigs` 是否为空。
- `WaveConfig.EnemyEntries` 或 `PathEntries` 是否为空。
- 旧单路径配置是否设置了 `TowerDefenseGlobalConfig.DefaultPath`。
- `WaypointPath.Waypoints` 是否至少有 2 个点。
- `TDEnemyConfig` 是否为空。

### 7.4 怪物生成但不移动

检查：

- `WaypointPath` 是否有效。
- `MoveSpeed` 是否大于 0。
- 是否每帧驱动 `UpdateFromUnity`。
- 是否 `engine.TimeScale = 0`。

### 7.5 主城不在预期位置

当前代码固定：

```csharp
SpawnMainCity(_tdConfig?.MainCityConfig, Vector3.zero);
```

`MapConfig.MainCityPosition` 当前没有被使用。如需地图配置主城位置，需要扩展 `TDBattleEngine.OnBattleStart()`。

### 7.6 UI 不刷新

检查：

- 打开 `TDHudView` 或 `TDHudViewBridged` 时是否传入 `TDBattleUIBridge`。
- UI 节点名是否与 `[UI]` 字段一致。
- View 是否在 `OnClose` 前保持订阅。
- `EventBus` 是否仍有效。

正确方式：

```csharp
var bridge = new TDBattleUIBridge(engine.Context);
UIRuntime.Instance.Open<TDHudViewBridged>(bridge).Forget();
```

### 7.7 UI 点击建塔不生效

当前 `TDTowerBuildView` 只发：

```csharp
UIRequestBuildTowerEvent(ETDTowerType towerType)
```

它没有世界坐标，也没有直接调用：

```csharp
TowerPlacementSystem.TryBuildTower(config, worldPosition, out tower)
```

因此完整 UI 建塔需要补充：

- 点击或触摸世界坐标获取。
- 根据 `ETDTowerType` 查找 `TowerConfig`。
- 调用 `TryBuildTower`。

### 7.8 塔不攻击

检查：

- `TowerConfig.AttackAbility` 是否为空。
- `TowerConfig.AttackRange` 是否覆盖到敌人。
- `TowerConfig.ProjectileDefinition` 是否正确。
- `RemoteAttackAbilityDefinition` 是否能被 `CombatAbilityComponent` 激活。
- 敌人是否是 `EEntityCamp.Enemy`。
- 敌人是否 `IsAlive`。
- `TDTargetingComponent` 是否能找到目标。

### 7.9 建塔失败

检查：

- 金币不足会导致 `SpendGold` 返回 false。
- 地面没有 Collider。
- `PlacementLayerMask` 没包含地面 Layer。
- `BlockedLayerMask` 命中了建塔点。
- 同一格已经被占用。

### 7.10 Roguelike 选择后不继续

检查：

- `RoguelikeChoiceSystem.SelectChoice(index)` 是否返回 true。
- 是否处于 `EBattlePhase.Choice`。
- 选择后会调用 `WaveManagerSystem.ResumeNextWave()`。
- 当前实现选择时 `engine.TimeScale = 0`，选择后恢复为 `1`。

## 8. 接入检查清单

最小跑通检查：

- [ ] 场景名为 `PVE`，或修改 `PveGameplayMode.SceneName`。
- [ ] 进入 PVE 时传入 `TDConfig` / `TowerDefenseConfig`。
- [ ] `StartImmediately=true`。
- [ ] `GameFacade.Update` 正常调用 `Gameplay.Tick(Time.deltaTime)`。
- [ ] `TowerDefenseGlobalConfig` 已配置。
- [ ] `MainCityConfig` 已配置。
- [ ] `WaypointPath` 至少 2 个点。
- [ ] `WaveConfig` 至少 1 波。
- [ ] `TDEnemyConfig` 已绑定到波次。
- [ ] 地面 Collider 和 `PlacementLayerMask` 正确。
- [ ] 如果要塔攻击，`TowerConfig.AttackAbility` 已配置。
- [ ] UI 打开时传入 `TDBattleUIBridge`。
